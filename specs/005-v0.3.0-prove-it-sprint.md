# Sprint Plan — v0.3.0 "PROVE IT"

**Repo:** `~/solana-defi-dashboard` (canonical) · **Starts from:** v0.2.0 (`56c17e5`, CI green, 119 tests)
**Duration:** 10 working days, solo · **Theme:** close the gap between what the code claims and what has been *seen to work*.
**Source:** POST-MIRROR PRODUCT AUDIT §4 + §11. Website is frozen and out of scope.

> **Sprint thesis.** v0.2.0's data plumbing is real, but its three headline claims —
> Orca positions render, the dashboard works in a browser, alerts reach a phone —
> have never been demonstrated end-to-end outside tests. v0.3.0 exists to make
> every user-facing claim observed, not asserted.

---

## Definition of done (sprint-level)

- Every story below carries **observed evidence** (screenshot, DB row, webhook
  receipt, CI artifact) linked in its checklist item — no "should work".
- Test suite ≥ 130, CI green on the release commit, ruff clean.
- `METRICS.md` updated for every changed label or metric.
- Release tag `v0.3.0` + GitHub release; old `~/Documents` tree archived read-only.

## Out of scope (do not touch this sprint)

Auth/multi-tenancy/billing, hosting decision, NLP/IL-predictor features,
Raydium (cut stands), anything touching transaction signing.

## Week 1 — Bugs and the three unproven claims

### S1 · Fix the db_path split-brain — **P0 bug, 0.5d**
`cli.py` and `trade.py` call `get_connection()` (default path) while the rest use
`config.db_path` → a custom path silently creates two databases.
- [ ] Single helper `conn_for(config)` in `src/db.py`; every call site uses it
- [ ] Regression test: custom `db_path` → CLI quote lands in the SAME db the UI reads
- **Evidence:** quote logged + `list_quotes` from the custom-path db in a new process

### S2 · Keyed RPC + WAL hardening — **1d**
- [ ] `rpc_endpoint` docs recommend Helius free tier; `.env.example` note
- [ ] SQLite `PRAGMA journal_mode=WAL; busy_timeout=5000` in `get_connection`
- [ ] Concurrency test: writer loop + reader loop on one db, no `database is locked`
- **Evidence:** live tick run with keyed RPC; flaky-skip in CI gone for 3 runs

### S3 · VaR/Sharpe honesty labels — **0.5d**
Computed from 15-second snapshot returns but labeled as if horizon-free.
- [ ] UI labels become "VaR (95%, intraday snapshots)"/"Sharpe (snapshot returns)" with help text stating the horizon; METRICS.md rows match
- [ ] Daily-resolution table `daily_values` materialized from snapshots (rollup at tick time) → second, clearly-labeled daily VaR when ≥ 2 daily points
- **Evidence:** screenshot of both metrics with horizon labels; test for rollup

### S4 · Wallet-scoped alerts + quote ownership — **1d**
- [ ] `alert_rules.wallet` (NULL = all watched, stated in UI); `quotes.wallet` optional column; process_alerts filters boundary/stop-loss per wallet scope
- [ ] Migration for existing dbs (ALTER + backfill NULL)
- [ ] Alerts page form gains wallet picker from watchlist
- **Evidence:** two rules for two wallets; sink test proves non-interference

### S5 · THE Orca real-position proof — **1.5d (highest risk, start early)**
The flagship has never rendered a real position.
- [ ] Add a wallet known to hold Orca CL positions to the watchlist (user's own, or discover one via Orca pool top-holders through `/v2/solana/pools/{addr}/positions/list?owner=` if it exists — timeboxed 2h discovery)
- [ ] Run daemon ticks; inspect the raw payload against `parse_position` expectations; fix field mapping to what Orca *actually sends*
- [ ] Capture the real payload as `tests/fixtures/orca_positions_real.json` (redact nothing — public data) and pin parser tests to it
- [ ] Positions page shows the position with live tick, chart after ≥ 2 ticks
- **Evidence:** screenshot of a real position rendered + fixture file + DB rows
- **Fallback if impossible in 1.5d:** S9 becomes "positions path behind an explicit
  *unverified* banner" and the sprint demoes everything else — never silently ship
  the claim.

### S6 · Browser smoke pass — **1d**
- [ ] Playwright script (dev-only, not shipped): start `defi-up`, walk all pages, add a wallet via form, submit an alert rule, click Get Quote, assert no console errors, screenshot each page to `docs/screens/`
- [ ] Fix whatever the first real render surfaces (layout, st.rerun loops, altair with 1-row history)
- **Evidence:** 4+ screenshots committed; script runs in CI (headless, network-mocked or skipped when rate-limited)

## Sprint risks

1. **S5 payload mismatch is the known unknown** — mitigated by day-1 start, 2h
   discovery timebox, and the explicit unverified-banner fallback.
2. Public endpoint rate limits — mitigated by S2 keyed RPC landing early in the week.
3. User-side blockers (wallet address, bot token) — request both on day 1; the
   sprint does not stall on them thanks to sink/fixtures paths.
4. Scope creep toward "hosted beta" — the out-of-scope list is the fence.

## v0.3.0 release criteria (binary)

A stranger's wallet, added in the browser, shows real balances, real Orca
positions with charts, one labeled intraday VaR, and one alert that arrived on a
phone — with screenshots in the release notes. If S5 cannot show a real position,
the release ships with the unverified banner and is labeled v0.3.0-beta.
